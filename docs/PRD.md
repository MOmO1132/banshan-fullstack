# 半山 BANSHAN · 产品需求文档（PRD）

## 〇、内容规模（v2）

| 内容 | 数量 | 备注 |
| --- | --- | --- |
| 手记 | 14 篇 | 4 个分类，300-1000 字，均带封面图与阅读时长 |
| 提问 / 回答 | 11 / 24 | 含代码块、表格、采纳标记 |
| 商品 | 25 件 | 5 个分类，3 张图 + 规格 + 产地 + 作者 |
| 买家评价 | 99 条 | 带星级，参与平均分与分布图 |
| 用户 | 8 位 | 积分、简介、头像色相 |

## 一、项目背景

课程文档给了三个示例：个人博客、问答社区、在线商城。本练习不分别做三个独立应用，
而是把它们合成**一个面向独立创作者的社区**——「半山」：写手记、提问题、逛市集。
好处是账号体系、导航、设计语言只需维护一套，也更容易看出「一个产品里三个业务域」
如何共享用户与积分。

## 二、角色

| 角色 | 权限 |
| --- | --- |
| 访客 | 浏览手记 / 问题 / 商品，不能发布、不能下单 |
| 登录用户 | 发布与编辑自己的手记、提问、回答、点赞、采纳（提问者）、加购、下单、管理地址 |
| 作者本人 | 编辑 / 删除自己的手记；采纳自己问题下的答案 |

## 三、功能清单

### 1. 账号（`/login`、`/register`、`/profile`）

- 注册：用户名 3-20 字符、邮箱格式校验且唯一、密码 ≥6 位，bcrypt 加密，注册赠送 100 积分
- 登录：用户名**或**邮箱 + 密码，签发 7 天有效 JWT，前端存 localStorage
- 个人中心：头像（按色相生成）、简介编辑、积分、四项统计（手记/提问/回答/订单/被阅读）
- 未登录访问受保护页面 → 跳登录页并记住来源，登录后自动返回

### 2. 手记（`/notes`）

- 列表：分类筛选、标题/正文/标签搜索、按时间或热度排序、每页 6 篇分页
- 详情：Markdown 渲染（GFM 表格、代码块、引用）、浏览量 +1、点赞、标签跳转
- 写作：左侧 Markdown、右侧实时预览；标题、标签、摘要、分类、封面主色可选
- 编辑 / 删除：仅作者本人可见入口，后端二次校验身份

### 3. 问山（`/qa`）

- 列表：最新 / 热门 / 待解决 / 零回答四种排序，标签筛选，搜索，每页 8 条
- 提问：标题 ≥5 字、描述 ≥10 字，发布扣 5 积分（余额不足拦截）
- 回答：提交加 10 积分，支持 Markdown
- 点赞：问题与回答都能点，同一用户对同一目标只能赞一次，可取消；点赞给作者加分
- 采纳：只有提问者能操作，一题只能采纳一次，答主 +30 积分，问题标记为已解决
- 积分规则：提问 -5 / 回答 +10 / 被采纳 +30 / 问题被赞 +5 / 回答被赞 +10

### 4. 市集（`/shop`、`/cart`、`/checkout`、`/orders`）

- 商品列表：分类磁贴 + 筛选、搜索、四种排序（最新 / 销量 / 价格升降），每页 8 件
- 商品详情：多图相册（缩略图切换）、规格表、库存/销量、数量选择、加入购物车、
  评分分布与买家评价、同类推荐
- 购物车：同一商品数量累加、不得超过库存、改数量、移除、实时算总价
- 地址：新增 / 选中 / 默认地址（互斥）、删除默认地址后自动指定下一条
- 下单：事务内校验库存 → 条件更新扣库存 → 写订单与明细（价格快照）→ 清购物车
- 订单：按状态筛选、模拟支付、取消（仅待支付，取消后库存退回）

## 四、页面结构

```
/                 首页：Hero + 三个模块入口 + 最新手记 + 讨论中 + 市集上新
/notes            手记列表（分类、搜索、排序、分页）+ 侧栏（分类/标签云）
/notes/:id        手记详情
/write            写手记（编辑模式复用，/notes/:id/edit）
/qa               问答列表 + 侧栏（热门标签、积分规则）
/qa/:id           问题详情（回答列表、投票、采纳、写回答）
/ask              提问
/shop             市集
/shop/:id         商品详情
/cart             购物车
/checkout         确认订单（选地址 / 新增地址 / 提交）
/orders           我的订单
/profile          个人中心（统计、我的手记、我的提问、我的订单）
/login /register  登录 / 注册
```

| | `POST /api/posts/:id/like` | 点赞 |

| | `POST /api/questions/:id/accept` | 采纳（+30） |

| | `DELETE /api/cart/:id` | 移除 |
| | `GET /api/addresses` | 地址列表（默认在前） |
| | `POST /api/addresses` | 新增（首条自动默认） |
| | `PUT /api/addresses/:id` | 修改 |
| | `DELETE /api/addresses/:id` | 删除（默认位顺延） |

统一响应格式：

```json
{ "code": 0, "message": "ok", "data": { } }
```

错误统一为 `{ code, message }`，HTTP 状态码语义化（400 参数、401 未登录、403 越权、404 不存在、409 冲突、500 服务器）。

## 六、非功能要求

- **安全**：密码 bcrypt（cost 10）、JWT 7 天、越权操作后端二次校验、Markdown 不渲染原始 HTML（防 XSS）
- **一致性**：下单 / 点赞 / 采纳 / 地址默认位全部使用事务
- **性能**：列表分页 + 索引；`answers_count` 冗余计数避免 N+1
- **可维护**：分层（routes / middleware / lib）、参数校验集中在 `lib/http.js`、错误统一中间件
- **部署**：前端 `vite build` 后由 Express 托管 `dist`，单端口 3001 即可运行

## 七、不做的事（刻意缩小范围）

- 不接真实支付，订单最多到「已支付」
- 不做图片上传，封面用「色相 + CSS 渐变 + 印记」生成
- 不做评论、关注、通知、搜索分词——属于扩展项
